## 🧬 Архитектура макросов

| Макрос | Описание |
| :--- | :--- |
| `CLASSIC_MERGE` | Стандартное двухпутевое слияние. Гарантирует **стабильность** сортировки. |
| `BITONIC_MERGE` | Слияние через построение битонической последовательности. Часто быстрее на ARM и современных x86 CPU за счет предсказуемости переходов. |
| `CMP_ASC` / `CMP_DESC` | Встроенные макросы для сравнения (по возрастанию и убыванию). |

---

## 📊 Производительность и сложность

Алгоритм Merge Sort обладает следующими характеристиками:
*   **Худшее время**: $O(n \log n)$
*   **Лучшее время**: $O(n \log n)$
*   **Среднее время**: $O(n \log n)$
*   **Затраты памяти**: $O(n)$ для временного буфера.



---

## ⚠️ Рекомендации

1.  **Типы данных**: При использовании со сложными структурами убедитесь, что макрос сравнения (`CMP`) корректно обрабатывает поля вашей структуры.
2.  **Память**: Библиотека использует `malloc` для создания временного буфера при вызове сортировки. Убедитесь, что у вас достаточно оперативной памяти для обработки массива размера `N`.
3.  **Компиляция**: Для достижения максимальной скорости рекомендуется компилировать с флагами оптимизации `-O3` и `-march=native`.

# Generic Merge Sort Macros (C)

![C Version](https://img.shields.io/badge/C-99%20%2F%2011-blue.svg)
![License](https://img.shields.io/badge/license-MIT-green.svg)

Высокопроизводительная реализация алгоритма **Merge Sort** на языке C, использующая макросы для генерации типобезопасного и эффективного кода. Проект поддерживает различные стратегии слияния, включая классический метод и оптимизированный битонический подход.

---

## 🚀 Основные особенности

*   **Type-Generic**: Благодаря макросам, вы можете генерировать функции сортировки для любого типа данных (`int`, `double`, `struct` и т.д.) без потери производительности.
*   **Zero-Overhead**: В отличие от `qsort`, здесь не используются указатели на функции, что позволяет компилятору выполнять агрессивный инлайнинг (inlining).
*   **Две стратегии слияния**:
    1.  **Classic Merge**: Стабильная сортировка с временной сложностью $O(n \log n)$ и памятью $O(n)$.
    2.  **Bitonic Merge**: Оптимизированная стратегия слияния, минимизирующая количество ветвлений (branching) и дружелюбная к кэшу процессора.
*   **Легковесность**: Весь проект состоит из одного заголовочного файла.

## 🛠 Использование

Для использования библиотеки достаточно подключить файл `merge_sort_macros.h` и объявить функцию для вашего типа данных.

### Шаг 1: Объявление (Declaration)
Используйте макрос `DECLARE_MERGE_SORT(TYPE, NAME, CMP, MERGE)`, чтобы создать функции:
```c
#include "merge_sort_macros.h"

// Генерирует функцию: void merge_sort_int_asc(int *arr, int n)
DECLARE_MERGE_SORT(int, int_asc, CMP_ASC, CLASSIC_MERGE)
Шаг 2: Вызов (Usage)

C
int main() {
    int data[] = {5, 2, 9, 1, 5, 6};
    int n = sizeof(data) / sizeof(data[0]);

    merge_sort_int_asc(data, n);

    for(int i = 0; i < n; i++) {
        printf("%d ", data[i]);
    }
    return 0;
}
